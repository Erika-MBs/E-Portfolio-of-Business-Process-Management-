  ## Artefact 1: BPMN diagram tutorial (Video)
  **Description**
  This resource is a video tutorial on BPMN (Business Process Model and Notation) developed by Lucid Software. This video explains how to create business process diagrams using standard BPMN symbols, showing how these elements represent the sequence of activities and decision points within a process. It provides a clear visual method that helps users understand how a process works from start to finish, enabling them to make informed decisions (Lucid Software, 2025). 
  
  ![Artefact 1](images/bpmn_art_1.png)
  *Figure 1: BPMN tutorial showing key modelling symbols (Lucid Software, 2025).*
  
  **Reflection**
  I chose this resource because it allowed me to deepen my understanding of BPMN as a common modelling language for various stakeholders, including business users, IT teams, and accounting staff. It helped me realise that BPMN is not only useful for mapping out a process, but also for understanding where each participant fits within the workflow. By using standard symbols, BPMN makes it easier to identify bottlenecks, redundant steps, and areas where the current process can be improved. All of this makes the resource one of the most widely used tools, as it demonstrates how visual models support communication, analysis, and process optimisation (Lucid Software, 2025).
  
  
  ## Artefact 2 – SIPOC 
  **Description**
  This artefact is a Six Sigma website that explains SIPOC as a high-level process mapping tool. It describes the main elements: Supplier, Input, Process, Output, and Customer. The resource explains how SIPOC helps define process scope and boundaries before developing more detailed models (Six Sigma, 2025).
  
  
  ![Artefact 2](images/SIPOC_ART_2.png)
  
  *Figure 2: SIPOC diagram illustrating suppliers, inputs, process, outputs, and customers in a business process (Author’s own work, 2026).*
  
  **Reflection**
  I chose this artefact because it made me realise that SIPOC is not only effective in Six Sigma, but can also be integrated with Lean, Kaizen, and BPM. This was important because it showed that SIPOC can be used as a foundation before moving into more advanced tools. It also gave me a clearer idea of the order in which different tools and techniques are used in practice, depending on the industry and situation (Six Sigma, 2025).

 ## Artefact 4: As-Is vs To-Be (Self-developed artefact)
  **Description**
  This artefact is an As-Is and To-Be process model for the analysis and improvement of a business process. The As-Is model is the existing process, and the To-Be model is the new process when the changes are implemented (ABPMP International, 2019, p. 161).
  
  ![Artefact 4](images/as_is_TO_Be_art_4.png)
  *Figure 4: As-Is and To-Be process models illustrating the transition from the current process to an improved and more efficient workflow (Author’s own work, 2026).*
  
  **Reflection**
  I chose this artefact because it helped me realise that an As-Is and To-Be model is not created directly, but usually after applying tools such as SIPOC, BPMN, swimlane diagrams, or gap analysis to understand the current process and identify weaknesses. This made me understand that process modelling follows a logical sequence: first understanding the process, then identifying gaps, and finally redesigning it into a better To-Be version. This is important because modelling supports process redesign and continuous improvement.
